# Canonical block 000 proof boundary and solver-call floor (v0)

This is a diagnostic follow-up to PR #49, not an authoritative scheduling change. The question is whether splitting the largest admitted mixed-radix method/mode block helps the **complete** scheduler after paying for an extra CP-SAT call. The current 64-activity, 20,000-placement and workface, 480-tick, 16-structure, canonical safety and deterministic-time bounds remain unchanged. The 160/120 case is never solved.

Merged main `4ad6b7afe02a969e5f0d4ff34a1c9b0b328334fd` was verified with eight green push workflows, including POC/browser smoke. Before editing, the public small, professional and 64/48 plan hashes matched PR #49's frozen values. No production scheduling module imports this experiment.

## Exact grouping and proof

The experiment discovers the highest-deterministic-cost production canonical block instead of assuming its index. On the 64/48 fixture it is `canonical_block:000`: eight method digits followed by 54 mode digits, no placement digits. The existing production block builder generates the same digit witness variables and the same exact mixed-radix coefficients. The challenger uses that builder's bounded mixed-radix implementation separately for the method prefix and the mode suffix; it does not invent a new weighting rule.

In lexicographic order, all methods precede all modes. Minimising the complete ordered method prefix and fixing its exact value before minimising the complete ordered mode suffix therefore yields exactly the same ordered digit vector as minimising their safe combined block. This equivalence depends on preserving every digit, its maximum and declared order. It does not apply if a target block includes placements or interleaves digit families: the existing smaller named-resource, professional and anonymous-group first blocks are explicitly marked inapplicable to this **two-family-only** challenger; their production plans still serve as semantic controls.

P0 is the actual public production path. P1 executes a fresh full LB1-finish, global-timing, two-sub-block and remaining-original-block proof path, with plan extraction and independent physical validation. P2 repeats that full path with one proof per target digit only. Both challenger plans match the entire production semantic projection and complete canonical vector; their experimental proof documents carry their own identity and are not production plans.

## Proof anatomy and cost accounting

Each P0/method/mode A/B/C probe starts from three cloned objective-free models with the same within-environment proto digest, variable count, constraint count and prior fixed values. A minimises the corresponding objective; B asks SAT at its exact optimum; C asks UNSAT at one unit better. B/C are diagnostic and **not added** to P0/P1 actual scheduling costs. Every query closes to its declared proof status.

The numerical census contains all digit maxima, radices and coefficients, the encoded maximum, coefficient extrema/ratio and bit lengths. In the retained environment the combined range has 60 bits, the method range 4 bits and the mode range 56 bits. The smaller ranges do not establish causation. Three fresh repeats each of objective-free context SAT, encoded-target-value-fixed SAT and every-target-digit-fixed SAT estimate invocation/presolve floor; wall min/median/max are observations, not correctness thresholds. A fresh optimiser at the same P0 stage is compared with the actual reused-solver production stage, separately in deterministic and wall terms.

An illustrative local run observed P0 11 calls and 0.278957 deterministic seconds for the complete policy, P1 12 calls and 0.310427, and P2 72 calls and 1.490308. P0's target block cost 0.081590; the P1 method proof alone cost 0.081516 and its additional mode proof 0.031543. For P0 the optimisation/SAT/UNSAT anatomy was 0.081590/0.031592/0.018323 deterministic seconds. Method anatomy was 0.081516/0.031543/0; mode anatomy 0.031543/0.031593/0.018324. A local complete-path wall observation was about 2.87/2.93/14.43 seconds (P0/P1/P2); it varies across runs and machines. The final exact-head artifact is authoritative for this PR's observations.

These observations do **not** justify adopting the semantic split: the extra proof increases deterministic work while a single wall comparison is noisy. The call floor quantifies the cost of solver invocation even when a target is fixed. Stage-size correlation, numerical range and elapsed time alone cannot identify a causal optimisation.

The source-bound JSON records full proof counters and per-repetition floors, complete policy cost, production hashes, small/professional/group controls, the one-placement activity ladder, the fixed-eight-activity density ladder and the classification-only 160/120 projection (64,068 raw / 64,032 deadline-eligible placements; first barrier 64 declared activities). No scale limit or canonical policy is changed. If final-head evidence retains the no-justification result, the next milestone should investigate the 160/120 placement/admission architecture rather than another solver micro-optimisation; it should **not** automatically raise any bound.
